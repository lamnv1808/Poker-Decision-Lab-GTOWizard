# V3.1 release gate report

Branch `feature/v3`, local only: **not pushed, merged or deployed.** The diagnosis is in `docs/V3.1_ISSUES.md`.

## 1. Root causes of the three complaints

| Complaint | Root cause | Type |
|---|---|---|
| Play as Hero repeats completed hands | Only 35 Hero scenarios. The picker went due → untried → **random**, so repeats were guaranteed once the untried ones ran out. There was no per-user completion record and no "you've seen everything" message. Simulator deals had no fingerprint. | backend selection + insufficient content + missing feature |
| Hands stop after one correct decision; no final board or opponent cards | 29 of 35 scripted scenarios have exactly one decision and end at an `end` node; 20 have no board. Folds ended the simulator hand with nothing revealed. The street indicator ticked off streets that were never reached. | content design + missing feature (+ one UI bug) |
| Hero mode does not affect Elo | Mostly **by design**: heuristic content has no validated answer. Production (V2) has no Fundamentals rating, so maths-verified scenarios updated nothing visible. The simulator could grade only ~7%. | missing feature + grading eligibility |

## 2. Implemented changes

- **History and selection:** a per-user `ScenarioHistory`, stored server-side and visible on every device. It is backfilled from existing runs. Each scenario has a status: New / In progress / Played / Mastered / Review due.
  - Pools: **New only (default)**, New + due, All, Played, Bookmarked, Weak.
  - Recently played scenarios are avoided in the broader pools.
  - An exhausted pool returns a clear message with options instead of repeating.
  - Replaying a completed scenario is practice only and earns no rated Elo.
  - A history reset needs confirmation and never deletes attempts or ratings.
  - Badges, "Hide completed", and progress shown as "N unique completed / 35 available".
- **Simulator diversity:**
  - An exact-deal key: a deal is never repeated.
  - A strategic fingerprint (seat, stack bucket, hand class, table, opponents): no repeat within the last 30 hands while alternatives exist.
  - Re-deals are bounded.
- **Full-hand continuation:** "Continue this hand" turns any scenario that ends mid-hand into a full hand from its exact state.
  - The authored board is kept; unknown cards come from the secure (CSPRNG) shuffle.
  - The scenario's actions replay exactly.
  - Correctness never ends a hand: play continues to fold, showdown or all-in runout.
- **Branch Challenge:** after a hand, make a modelled Villain fold, call or raise instead and play on. These branches are never recorded.
- **Hand summary:**
  - Winners with hand category, pots, and how and on which street the hand ended.
  - Optional **reveal of folded cards and the hypothetical runout**: simulator-only and labelled as such.
  - A readable action log, and streets that were never reached are shown as skipped.
- **Coverage:** a **solver flop table** reproduces the 85-flop library's exact assumptions.
  - Hero's flop decisions are graded against the solver (Strategy), and Villains use solver frequencies there.
  - The tree's sizes are offered as buttons (sizes only, never frequencies).
  - Solver-equivalent spots share a familiarity family, so repeating them can't farm Elo.
- **Feedback:**
  - Every decision is labelled Solver verified / Math verified / Reviewed strategy / Assumed-range model / Heuristic coaching / Not evaluated.
  - Ungraded decisions get model-based coaching, clearly marked "not a grade".
  - Rubric grades on heuristic scenarios are labelled coaching grades.
  - Villain "why" explanations show the archetype, the hand strength as the model saw it, and its frequencies.
- **Villain model `sim-v1.1`:** facing a 2/3-pot bet, fold rates were 10–22% (unrealistically sticky). They are now Nit 49%, TAG 46%, LAG 29%, Maniac 25% and Station 14%. The model version is stored per hand, so older hands rebuild exactly as dealt.
- **Practice progress (not Elo):** `/api/training-progress` and a dashboard panel show decisions (graded and ungraded), full hands and unique situations, street coverage, confidence calibration, review queue, learning streak, and each module's Strategy and Fundamentals contribution.
- **Mixed Training:**
  - Adds Hero scenarios, Read the Villain, Real Hand Replay and solver-flop hands.
  - Mixes: Balanced / Hero-focused / New only / Weak / Due.
  - No item type may exceed ~40% of a session.
  - Uses the history-aware picker; exhausted pools drop out of the session.
  - The summary splits answers into Strategy-rated, Fundamentals-rated and ungraded.

## 4. Database migrations (all additive; nothing reset or rewritten)

1. `sim_hands`: `SimHand` table.
2. `rating_model_state`: `RatingModelState` table.
3. `training_session_config`: nullable `TrainingSession.config`.
4. `sim_hand_secure_deal`: nullable `SimHand.deal`.
5. `scenario_history`:
   - `ScenarioHistory` table, **backfilled** from existing `ScenarioRun`s;
   - `SimHand.fingerprint`, `exactKey`, `origin` and `bookmarked`;
   - `UserPreference.historyResetAt`;
   - indexes.
6. `v31_indexes`: `DecisionAttempt(userId, familyId)` and `DecisionAttempt(sessionId)`.

Verified against a copy holding the full real dataset: 52,523 hands, 78,704 accepted decisions and 1,097 draft annotations. All are unchanged, and no annotation was verified.

**Cannot be graded today, and why:**
- deep-stack preflop opens, 3-bets and calls: no preflop solver library beyond push/fold;
- turn and river play;
- flops outside the 85 solved ones;
- multiway postflop;
- bet sizes outside a solved tree;
- ICM and PKO effects.

None of these are given invented EVs.

## 6. Full-hand QA (500 hands, rule-based Hero bot, `apps/server/scripts/qa-sim.ts`)

| Metric | Result |
|---|---|
| Hands reaching a valid terminal state | **500 / 500** |
| Avg decisions per hand | 1.99 |
| Terminal street | preflop 45.8% · flop 4.6% · turn 2.4% · river 47.2% |
| Reached showdown | 43.6% |
| Invalid action responses | 0 |
| Chip-conservation failures / state corruption | 0 |
| Exact duplicate deals | 0 |
| Situation repeated within the previous 30 hands | 0 (500 distinct situations) |
| API latency | median 37.5 ms · p95 78 ms · max 140 ms |

The street distribution reflects the bot's style: it folds weak preflop hands and rarely bets postflop, so many hands check down. With a Hero who bets every street, Villains fold 14–49% depending on type (see the model change in section 2). The showdown rate was not tuned.

**Browser runs:** 20 complete hands each on desktop (1366×900) and mobile (Pixel 7), driven through the real UI by Playwright with random legal choices. Results: 20/20 and 20/20 reached the result screen, 0 console errors, no horizontal overflow. I inspected the screenshots myself, which led to three fixes:
- the solved-tree sizes are now shown, after a decision fell off-tree;
- a "none — all five cards were dealt" label for the runout;
- the progress bar no longer strikes through future streets during play.

## 8. Remaining limitations

- About 84% of simulator decisions on random tables are coaching, not grades. Raising this honestly needs more solver data: a preflop open/3-bet library and turn/river nodes.
- Villains are heuristic (labelled). Solver frequencies are used only in exact push/fold and library flop spots.
- Curated content is still 35 Hero and 9 Villain scenarios. After that, New-only says so and points to unlimited full hands.
- Continuations of curated scenarios use TAG Villains by default.
- Real Hand Replay contributes to Strategy only once annotations are verified by a human. None are yet.

## 9. Storage and performance

- A `SimHand` row is ~3–6 KB (config, deal, steps), so ~1,000 hands ≈ 5 MB. `ScenarioHistory` and the new indexes are negligible.
- Production DB: 443 MB of 1 GB on the free plan, which **expires 2026-12-01**: upgrade before deploying.
- With the full 52k-hand dataset, warm timings are 10–60 ms for the new endpoints and `/real/next` ~0.1–0.17 s. The first call after a restart can take 2–3 s while caches warm.

## 10. Deployment and rollback

**Deploy (only on your approval):**

```
git checkout main && git merge --ff-only feature/v3 && git push origin main
```

Render builds, and `prisma migrate deploy` applies the six additive migrations, including the history backfill.

**Smoke test:**
- `/api/health`;
- log in, then open `/hero`, which should show "N unique completed";
- play a hand on `/play`, then reveal and branch;
- check the dashboard's "Training activity".

**Rollback:** use Render's "Rollback" to the previous deploy. The migrations only add tables, nullable columns and indexes, so the previous code runs unchanged against the migrated schema; no down-migration is needed. A Postgres backup before deploying is recommended, and point-in-time restore is available on paid plans.
